Corrupted Hunllef Simulation
Web Innovations Project

Author: Alex Crosby
Module: Web Innovations


1. Project Overview

This project is a browser-based simulation of the Corrupted Hunllef encounter from Old School RuneScape.
The purpose of this project is to provide a risk-free and accessible environment for players to practice and improve their performance. 

This project was demonstrates advanced JavaScript programming, interactive systems, and real-time user feedback.

2. Key Features

- 12x12 tile-based arena
- Tile-based player movement and pathing
- Boss behaviour with alternating combat styles
- Projectile-based combat with damage mitigation
- Environmental mechanics including:
  - Dangerous floor tiles
  - Tornadoes
- Health system with visual and numeric feedback
- Boss health bar and hit splats
- Accessibility features:
  - God Mode
  - Simulation speed control
  - True tile indicators with customisation options


3. Technologies Used

- HTML5
- CSS3
- JavaScript
- Three.js (for 3D rendering and scene management)

The Three.js library is included locally within the `vendor` directory. 
No external CDN or internet connection is required to run the project.


4. Running the Application

Due to JavaScript module loading restrictions, the application must be run via a local web server. 

Recommended method:

VS Code Live Server
- Open the project folder in Visual Studio Code
- Install the Live Server extension
- Right-click index.html and select Open with Live Server

Once running, click the Start button in the application to begin the simulation.


5. Controls 

- Left Click: Move, attack, and interact
- Mouse Wheel: Zoom camera in and out
- Keyboard / Mouse (Alt + Right Click): Rotate camera

Detailed instructions can be found in the User Guide.


6. Technical Requirements

- A modern web browser (Chrome, Edge, or Firefox recommended)
- A basic modern PC or laptop capable of running WebGL applications


7. Testing

This project was tested on a clean local environment using a local web server to ensure all assets load correctly and all features function as expected.


8. Known Limitations

- The simulation prioritises mechanical accuracy over visual fidelity.
- The project is intended as a practice tool rather than a complete recreation of the original game.
- Some timing and visual elements are simplified for clarity and accessibility.
